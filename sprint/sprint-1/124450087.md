## Tugas #11 — Rancangan skema SQL Silver: kunci primer, tipe kolom, dan pilihan basis data

1. **Yang dikerjakan:**
   - Menyusun DDL skema relasional `src/gold/silver.sql` untuk memuat tabel katalog `seri` dan tabel `silver` dengan tipe data baku, primary key komposit `(sumber, seri_kode, wilayah_kode, periode, rincian, _berkas_raw)`, foreign key `seri_kode REFERENCES seri(seri_kode)`, serta batasan integritas `CHECK` (rentang wilayah, jenis periode, panjang sha256, dan validasi rentang batas nilai).
   - Mengimplementasikan skrip pemuat DuckDB `src/gold/muat_sql.py` yang memuat Silver pertama ke `data/gold/gudang.duckdb` dan memvalidasi keutuhan jumlah baris.
   - Menambahkan berkas referensi katalog metadata seri di `docs/seri.csv`.
   - Menulis laporan pertimbangan arsitektur dan perbandingan model tabel vs dokumen di `reports/basis-data.md`.
   - Mencatat keputusan `K-031` di `log-keputusan.csv` dan memperbarui metrik `baris_sql` di `results/124450087/metrics.json`.

2. **Yang dipelajari:**
   - DuckDB sangat ideal untuk lapisan analitik (Gold): beroperasi secara *serverless* (file berbasis lokal), memiliki mesin eksekusi *vectorized columnar* yang cepat untuk agregasi/pivot, dan mendukung interoperabilitas langsung dengan Parquet tanpa overhead import/export.
   - Perbandingan Tabel Relasional vs Dokumen JSON: Respons mentah API BPS berupa dokumen bersarang hierarkis yang cocok untuk arsip dan preservasi metadata asli (`data/raw/`). Namun untuk agregasi, filtering, dan verifikasi integritas analitik, format tabel relasional terstruktur dengan primary key dan batasan CHECK pada Silver/Gold jauh lebih andal dan efisien.

3. **Rencana / Tindak Lanjut Sprint 2:**
   - Memanfaatkan DuckDB untuk membangun kueri SQL panel dimensi provinsi × periode × indikator pada tahap Gold.
   - Membandingkan performa analitik antara pandas dan DuckDB.
